- 18 项 CPU 验收、GPU R50/ViT 事务恢复与错误 LR 拒绝的回执为 PASS；交付审计声明复核 **2,133** 个证据文件、P1 40 个现存 checkpoint、P2 128 个现存 checkpoint。
- 当前项目+环境 **44.176095 GiB / 60 GiB**；P3 目标 200 GiB **尚未落实证据**。我审核的是 GitHub 回执与数据互相符合的程度，没有直接重新运行服务器二进制 checkpoint。

### 科研解释边界与预设主比较

根据原协议，两项**不可事后改动**的主比较为：CIFAR-100 / ViT IN21K 的 Linear Probe 对 Full FT；SVHN / R50 IN1K 的 Adapter 对 Full FT。

P2 验证集（仅 seed=123，15 轮）两项对应差值分别约为 **−4.83**、**+0.06 个百分点**。原稿相应报告 **+0.46**、**+3.79 个百分点**，但基准、训练协议与评价口径不同，**不能做严格同条件因果比较**。应把这种变化当作 P3 必须验证的证据，而非淘汰实验或更换主假设的理由。

P2 16 个选择中 12 个位于网格边界，意味着选中的只是冻结三档搜索范围内的最优候选，不保证全局最优。禁止临时扩网格、改变阈值、重复调参 seed、按预测排名删除策略。

## 3. 正式矩阵和冻结配方

- 主实验 = `2 datasets × 2 backbones × 4 methods × 5 seeds = 80 runs`，每 run **50 完整 epochs**；最多 4,000 epochs，失败按真实完成数计数。
- 数据 `cifar100`、`svhn`；骨干 `resnet50.a1_in1k`、`vit_base_patch16_224.augreg_in21k`；策略 `scratch`、`full_ft`、`linear_probe`、`adapter`。
- 正式种子 **17、42、2026、3407、65537**；与 P2 选参 seed 123 完全分离。P3 每 run 从冻结预训练权重（或 scratch 随机初始化）**全新开始**，禁止继承 P2 checkpoint；只在该 P3 run 内按合法事务状态恢复。
- 每组所选 LR 以 `selected_hparams.json` 为单一来源；**禁止手抄、就地编辑或把 P2 选参结果重新计算后不留痕地覆盖**。Full FT 分类头学习率继续是主干的 10 倍。
- Batch 32、梯度累积 4、effective batch 128；AdamW、更新步为单位的线性 warmup 5 epochs + cosine 50-epoch horizon；BF16 autocast / FP32 参数及 loss / TF32 OFF / 禁止擅自切 FP16、torch.compile 和改变 Adapter 拓扑。
- 冻结原 train/validation split（CIFAR100 45,000 / 5,000；SVHN 65,931 / 7,326），数据增强与原协议相同；SVHN 不做水平翻转。禁止使用官方 test 进行训练、调参、提前停止、错误定位或性能报告。
- 每一 `dataset×backbone×seed` 四策略维持相同初始分类头与可复现的数据顺序、增强；保留参数白名单与 BN buffer 验收。

## 5. P3-B 正式训练前六项硬性验收门（缺一不可）

1. **数据与参数身份**：确认 Git 提交、`configs/protocol.json`、原始 split、权重 exact revision + SHA、环境锁、`selected_hparams.json` 文件 SHA 都能核验。当前 `reports/P3_proposal.json` 中 **80/80 个草案运行的 `checkpoint_revision` 与 `checkpoint_sha256` 仍为 null**，这只可留在草案中；**正式 resolved config 必须补全并绑定 `records/assets.json`**，不能直接将草案执行。清理旧模板中的无效 `budget_required_at` 等过期状态字段。
2. **80-run 入口**：逐项声明 phase=P3、seed、LR、fresh initialization、50 epoch、权重/头身份、授权证明及所属 GPU。正式 80 个 run_id 唯一，按 5 个 seed 完整登记；不根据 P2 准确率修改运行数量或顺序。
3. **数值/恢复/事务门**：复用已验收的 P2 不可变 epoch 代次 + 单一提交指针语义，适配 50 epochs 与多 seed；静态、CPU 故障注入和小 GPU 恢复验收必须覆盖全部 epoch 提交边界、RNG、sampler、optimizer、scheduler、最佳验证模型、时间/费用不回退、代码/科学配置身份不匹配拒绝、原子 GC、非法恢复拒绝。事故不得篡改历史源 commit/epoch 状态。小 GPU 验收成本计入 160 GPU-hours。
4. **资源硬门**：已核实项目+独立环境 **至少 200 GiB 的实际分配额度**，有最大 checkpoint 双文件原子保存所需空间；项目预算文件包含新的独立 `160 GPU-hours` 阶段上限，P2 台账保持只读。两卡每任务一卡、每卡最多一运行；父进程负责共同实时预算、退出 buffer、进程组结束、attempt 最终结算及失败回收。任何预测超支、资源不足或不可解释不一致应停发新任务、留证据。
5. **共同时间预算冻结**：四个 B 取本合同第 4.2 节的源 JSON 全精度值，冻结到独立 `records/p3/time_budget_frozen.json`，记录选择依据 SHA、UTC 时间、每组选择原因和三预算点；只依据计时，不依据 Top-1。prefix checkpoint 必须有不可变 hash、事务完成单调时刻、role 与预算点归属。
6. **测试隔离和 fail-closed**：修复当前 `src/evaluate.py` 的 `if authorization file exists and not authorized` 式**授权文件缺失则跳过检查**的行为。改为缺失/损坏/版本或签名身份不一致均立即拒绝；必须有 **P3 封存 + 冻结 evaluation manifest + 单独集中测试授权** 才可在 TestData 构造之前解锁。修复同一 run 多个 `budget_prefix` 使用相同 `run_id+role` 文件名而覆盖输出的问题。`evaluation_id` 至少区分 run、角色、预算点、checkpoint SHA；按 run + checkpoint SHA + 预处理与精度身份可缓存推理，但每个角色结果记录独立。P3-A 可以用合成输入 CPU 单测/受控 GPU 假数据验收，绝不可读取官方测试标签或生成正式 test 预测。

**全部门禁**必须在受保护的新分支上完成、生成机器可读 PASS 回执并记录真实服务器资源凭证，再允许父调度器解除 P3-B `not_authorized` 状态。若缺失 200 GiB 配额，不得用“共享盘仍有大量空间”绕过；若只能满足较小配额，应先另行提交明确的存储保留修订供用户批准。

## 6. 训练调度与风险边界

- 首批正式 run 要覆盖 R50/ViT、至少两种参数策略以及两个物理 GPU 的入口验收，但测试模型精度不能成为继续/停止其他预注册 run 的依据。不得发明额外大规模 pilot；必要正式 run 的前若干 epoch 同时用于校准。
- 以运行时长估计平衡两卡队列，不将某策略永久绑到同一 GPU；结果保留 GPU UUID、驱动和配方，双卡并行占用与父账本双计正确。
- 每 run 每轮保存 train/val、最佳验证 epoch、累计训练/验证/保存时间、原子代次 SHA、数值门禁、内存峰值、有效 optimizer 更新数与总处理样本。统一 50-epoch horizon，不改成“本次还剩多少 epoch”的新学习率曲线。
- `numerical_failure`、`oom`、`stalled` 与 `infrastructure_interrupted` 必须区分。非有限 logits/loss/grad/updated params/optimizer 状态立刻中止污染更新，并保留最后合法 checkpoint 和诊断元数据。恢复只针对具备同一科学配置身份的基础设施中断。若是科学实现错误，旧受影响 run 标记 invalid_protocol 并暂停审核，而不是静默重跑选好的结果。
- 5 seeds 分母固定，即使个别失败也不删种子、不顺延重试直到得到好看的五次，不擅自改 LR。正式主比较需要双方 5/5 完成才可按协议做主 inferential claims；条件结果另列。
- 发生任何预测占用超 160 GPU-hours、冻结输入身份改变、磁盘临界、无法确定的旧事故再现、异常恢复、真实测试集触达，应安全 drain、停止新任务并报 PI。**不因阶段暂停而自动取消原有失败证据。**

## 7. P3 终点与集中评价的独立门

P3-B 的正确终点是 **80 个注册运行都有最终状态**（不必伪造 80 个成功），留下完整 50 epoch/失败记录、`best_val`/`last`/prefix checkpoint、各预算点是否可得、计时与存储台账、科学配置和环境 SHA。P3 的最终结果仍是**验证集选择/训练稳定性与资源证据**，不是测试集指标。

由独立程序生成 P3 seal 和 evaluation manifest 草案，至少含 80 run 的终态、冻结的 P2 选择文件 SHA、全部评价角色、每个 checkpoint 的 SHA、每个 prefix 预算点与不可变完成时刻、严格的唯一评价身份、重复复用计划。seal 创建后**集中测试授权仍为 false**，禁止运行官方 test 评价。

待用户再次审核上述封存收据并明确批准集中测试后，才允许执行官方 test Top-1、macro-F1、balanced accuracy、NLL、逐样本预测与 confusion matrices。测试不能反过来选新的 LR/checkpoint。下游统计按原合同主比较与 paired 5-seed t 区间、两项预注册优势检验的 Holm 校正、ViT-CIFAR LP 对 FT 的 −0.5 pp 非劣界限执行，失败保留完整 5-seed 分母。不会把单种子验证集分差宣称为正式发表结论。
