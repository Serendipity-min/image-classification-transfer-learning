# P3 阶段审核提案（未授权）

P2 证据已冻结，本文件仅提出下一阶段资源和实现要求；不启动 P3 或测试。建议下一次单独授权 160 GPU-hours，并确认至少 200 GiB 项目及环境分配或明确替代保留政策。当前 60 GiB 与旧 100 GiB 规划线不覆盖该完整保留情景。

16 个所选配置 × 原定五种子 17、42、2026、3407、65537 = 80 个正式 run；全部从原始初始化重新训练 50 轮，不续训 P2。所选 LR、P2 run 和 selected_hparams SHA 已解析进入配置草案。

| 预算组成 | GPU-hours 提案 |
|---|---:|
| 80-run 基础训练外推 | 121.333 |
| 最多 240 个额外时间切片保存情景 | 0.167 |

外推采用各配置所选 P2 候选第 2 轮起的完整 epoch 事务时间中位数，加实际固定和首轮额外开销。P2 实测已包含当时并发环境，不再次重复乘同一个慢化因子。它是估算，须在正式运行中继续按共享台账执行新的独立硬上限。

额外切片保存按每个 run 最多三次完整事务费用保守计；评价按 80 best + 80 last + 最多 240 prefix，用 P2 验证时序按官方测试集样本数缩放，尚未执行任何测试评价。重复 checkpoint 的预测可去重复用，草案未预先据此压低上界。

## 存储与进入条件

保留当前 P1/P2 全证据、P3 best/last/delta、每 run 三个额外完整切片并加 25% 的存储情景约 **182.80 GiB**。本次 60 GiB 仅覆盖已授权 P2；此新情景需要 PI 明确资源和保留政策，不能自动沿用为已获保障。

P3 入口验收必须覆盖 80-run 配置、不可变 prefix 提交及时间冻结、P3 seal 与 evaluation manifest，以及唯一 evaluation_id、run+checkpoint SHA 预测复用和 TestData 构造前的严格身份/状态/角色/预算时刻验证。原评价入口对多个 prefix 的命名覆盖问题须在开放测试前解决。

每个预算点只接受预算内已完成验证并提交保存的 checkpoint；无合格模型就报告不可用。正式失败保留五种子分母，主比较、配对分析、置信区间、Holm 校正及非劣效界限沿用原合同。
