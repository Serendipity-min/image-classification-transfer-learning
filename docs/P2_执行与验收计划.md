## 执行边界

- 独立入口 `p2_train.py` 只读取原矩阵 48 个 P2 候选，seed123、15 轮、50 轮调度、5 轮 warmup。各候选从原始初始化开始。
- 独立 P2 台账硬封顶 30 GPU-hours。GPU 验收、失败、恢复、技术重跑和退出均在其中；不挪用 P0/P1 余量。
- 每次运行由独立守护进程监测 owner 存活、两卡共享预算和统一 drain 期限；子 finally 不是成本事实的唯一来源。CPU RSS 终值、主进程峰值和进程树采样峰值分别命名。
- `current.json` 是 epoch 事务的单一提交点，绑定不可变 last/best、科学配置 hash、完整 epoch row 和累计成本。原子发布前的代次不用于恢复。日志从提交链幂等重建；sidecar 不能回滚或替代父成本账本。
- 同一 run 保留当前 best、最新 resumable last 和任务增量；被替代的普通 epoch 代次按已记录身份回收，不无限复制 15 份 optimizer。失败现场单独保留，所有候选的日志/提交清单均保留。
- 每个候选的科学 hash 包含 LR、索引、轮数、batch/累积、精度、优化/调度、协议/划分/权重/依赖及实现范围。运行设备、attempt、剩余预算属于运行元数据。
- 选参严格比较第 13–15 轮验证 correct 总和；真正并列选较小数值 LR。基础设施未完成阻止配置选择幸存者；全数值失败显式 blocked。

## 校准和停止保护

首批登记候选为 CIFAR-100/R50 Full FT lr2 与 SVHN/ViT Adapter lr2，各自完整第 2、3 轮校准对应 P1 基线；它们仍完成原定 15 轮，不另增 pilot。后续可用候选也记录同样长窗口。两个设备按每策略各六候选预分配，并据基线时长平衡负载。

慢化超过 10%、总成本预测越过 30 GPU-hours、存储到达 54 GiB 预警或退出余量不足时暂停发新任务并输出具体原因。当前任务只能在共享硬上限内到合法边界；硬停保留最近完整事务。不得缩短候选轮数或跳过验证以凑预算。临时原子写入前同时检查真实磁盘和已确认额度至少保留 5 GiB。

输出全部候选、选参文件、父 attempt 台账、checkpoint hash、存储回执及 P3 80 条配置/时间切片/完整预算草案后停止。P3 seal、唯一 evaluation_id 与测试身份检查的正式实现和验收仍属下一次阶段审核。
